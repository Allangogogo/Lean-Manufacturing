# 安灯（Andon）

## 工具名称

| 语言 | 名称 |
|------|------|
| 中文 | 安灯系统 |
| 英文 | Andon System |
| 日文 | 安灯（あんどん / Andon） |

---

## 定义与目的

安灯是一种实时异常视觉告警系统，源自丰田生产方式。当生产线出现质量异常、设备故障、物料短缺或其他问题时，操作员可以通过拉动安灯绳或按下安灯按钮，发出即时的视觉和/或听觉信号，通知相关人员立即响应和处理。

安灯的核心理念是**"问题发生时立即暴露，而不是隐藏"**。它将生产现场的问题从"事后发现"转变为"实时暴露"，为快速响应和根本原因分析创造条件。

### 核心目的

- **即时暴露异常**：让问题在发生的第一时间被所有人看到
- **快速响应处理**：通过明确的升级协议，确保问题在最短时间内得到处理
- **防止不良品流出**：及时停线防止批量质量事故
- **培养问题意识**：让团队养成"发现问题即改善"的文化
- **积累改善数据**：安灯记录为持续改善提供数据支撑

---

## 关键原则

### 原则一：任何人都可以拉动安灯

安灯系统赋予每一位现场操作员发现问题时立即叫停的权利和责任，无论其职级高低。这是"质量是制造出来的"理念的具体体现。

### 原则二：停线不是失败，隐藏问题才是

安灯拉动后产线暂停并不意味着生产失败。相反，它代表团队有勇气面对问题并致力于解决它。管理者应鼓励安灯拉动，而非惩罚。

### 原则三：快速响应是核心

安灯的价值不在于发出信号，而在于信号发出后的响应速度和处理质量。建立明确的响应流程和时间目标是安灯系统成功的关键。

### 原则四：根本原因分析不可少

每次安灯事件都应进行根本原因分析（RCA），防止同类问题重复发生。安灯记录的数据应定期分析，识别系统性的改善机会。

### 原则五：持续优化升级协议

安灯的升级协议应根据实际运行情况持续优化。过慢的升级会导致问题扩大，过快的升级会导致管理层疲劳。需要在响应速度和管理效率之间找到平衡。

## 实施步骤

### 第一步：确定安灯触发条件

明确什么情况下应拉动安灯：

| 触发类型 | 具体场景 |
|----------|----------|
| 质量异常 | 尺寸超差、外观缺陷、性能不合格、连续不良 |
| 设备故障 | 设备停机、异常振动、异响、温升异常 |
| 物料短缺 | 原材料不足、半成品断供、包装材料缺乏 |
| 安全隐患 | 安全防护失效、人员受伤风险、环境异常 |
| 工艺偏差 | 工艺参数超出控制范围、工艺条件异常 |
| 信息异常 | 作业指导书缺失、生产信息不符、标识不清 |

### 第二步：设计安灯信号系统

**三色信号设计**

| 颜色 | 含义 | 响应要求 |
|------|------|----------|
| 🟢 **绿色** | 正常生产 | 无特殊要求 |
| 🟡 **黄色** | 需要支持/预警 | 班组长在1分钟内响应 |
| 🔴 **红色** | 停线/严重异常 | 班组长立即到场，必要时升级到车间主任 |

**物理实现方式**
- 安灯塔灯：安装在每台设备或工位上方的多色信号灯
- 安灯拉绳/按钮：操作员可快速触发的物理装置
- 声光报警器：配合视觉信号的听觉提醒
- 电子看板：实时显示安灯状态的显示屏

### 第三步：制定升级协议

建立分级响应机制：

```
Level 1（操作员 → 班组长）
  │ 触发条件：黄色/红色安灯
  │ 响应时间：1分钟内
  │ 处理权限：简单故障排除、换刀换模、小幅调整
  │ 超时升级：5分钟未解决 → 升级至Level 2
  │
Level 2（班组长 → 车间主任/工程师）
  │ 触发条件：Level 1无法解决
  │ 响应时间：5分钟内
  │ 处理权限：设备维修、工艺调整、质量判定
  │ 超时升级：15分钟未解决 → 升级至Level 3
  │
Level 3（车间主任 → 生产经理/质量经理）
  │ 触发条件：Level 2无法解决或影响重大
  │ 响应时间：15分钟内
  │ 处理权限：停线决策、跨部门协调、客户沟通
  │
Level 4（生产经理 → 总经理）
  │ 触发条件：重大质量事故或安全事件
  │ 响应时间：30分钟内
  │ 处理权限：全面停线、召回决策、外部沟通
```

### 第四步：建立安灯响应流程

```
异常发生 → 操作员拉动安灯 → 信号发出（灯光+声音）
    ↓
班组长到达现场 → 初步判断 → 尝试快速修复
    ↓
  是否解决？
  ├── 是 → 记录原因 → 恢复生产 → 安灯解除
  └── 否 → 升级至Level 2 → 工程师介入
           ↓
         是否解决？
         ├── 是 → 记录原因 → 恢复生产 → 安灯解除
         └── 否 → 升级至Level 3 → 管理层介入
```

### 第五步：安灯数据记录

每次安灯事件应记录以下信息：

| 记录字段 | 说明 |
|----------|------|
| 安灯编号 | 唯一标识 |
| 触发时间 | 精确到分钟 |
| 触发工序 | 发生异常的工序 |
| 异常类型 | 质量/设备/物料/安全/工艺 |
| 异常描述 | 具体现象描述 |
| 响应人员 | 到场处理的人员 |
| 响应时间 | 从触发到到场的时间 |
| 处理时间 | 从到场到恢复的时间 |
| 处理措施 | 采取的临时和永久措施 |
| 根本原因 | 分析得出的根本原因 |
| 是否升级 | 升级到了哪个级别 |

### 第六步：安灯数据应用

定期（每日/每周/每月）对安灯数据进行分析：
- 安灯频率趋势分析
- 各工序安灯分布
- 异常类型帕累托分析
- 响应时间达标率
- 重复问题识别
- 改善措施跟踪

## 安灯在产品检测中的应用

### 尺寸超差处理流程

**场景**：机加工工序操作员发现连续3件产品头部对角尺寸超差

```
步骤1：操作员发现异常
  - 目视检查发现头部对角尺寸偏大
  - 使用卡规快速测量确认超差

步骤2：拉动安灯（红色）
  - 立即停机
  - 拉动安灯绳
  - 将可疑品放入红色标识箱

步骤3：班组长响应（1分钟内）
  - 到达现场
  - 查看首件记录和最近的巡检记录
  - 确认问题范围（最后合格件到发现件之间的数量）

步骤4：初步处理
  - 对可疑品进行全检
  - 合格品隔离放行，不合格品报废
  - 分析可能原因：模具磨损？材料批次变化？设备参数偏移？

步骤5：工程师介入（5分钟内）
  - 检查模具状态
  - 测量关键尺寸
  - 对比材料质保书
  - 检查设备参数记录

步骤6：采取措施
  - 更换或修复模具
  - 调整设备参数
  - 首件确认合格后恢复生产

步骤7：记录与改善
  - 填写安灯记录表
  - 更新模具寿命管理表
  - 优化巡检频次
```

### 安灯在其他工序的典型应用

**精加工工序**
- 量规检测不合格
- 表面滑纹或烂牙
- 头部内六方/内六方成型不良

**热处理工序**
- 炉温偏差超出控制范围
- 网带速度异常
- 硬度抽检不合格
- 炉内气氛异常

**表面处理工序**
- 镀层厚度不合格
- 外观异常（起泡、脱落、色差）
- 挂具接触不良
- 镀液参数异常

**包装工序**
- 标签信息与实物不符
- 数量偏差超出容差
- 包装方式不符合客户要求

## 关键指标/KPI

| 指标 | 定义 | 计算方法 | 目标值参考 |
|------|------|----------|-----------|
| **安灯拉动频率** | 单位时间内安灯触发次数 | 安灯总次数 / 生产时间 | 趋势分析（初期上升属正常） |
| **平均响应时间** | 从安灯触发到响应人员到场的时间 | 总响应时间 / 安灯次数 | Level 1: < 1分钟 |
| **平均处理时间（MTTR）** | 从安灯触发到恢复生产的总时间 | 总处理时间 / 安灯次数 | < 15分钟 |
| **升级率** | 需要升级到更高级别的安灯比例 | 升级次数 / 总安灯次数 × 100% | < 20% |
| **重复问题率** | 同一根本问题再次触发安灯的比例 | 重复安灯次数 / 总安灯次数 × 100% | < 5% |
| **安灯解决率** | 在现场直接解决无需升级的比例 | 现场解决次数 / 总安灯次数 × 100% | > 80% |
| **响应达标率** | 在规定时间内响应的比例 | 达标次数 / 总安灯次数 × 100% | > 95% |
| **停线时间占比** | 因安灯导致的停线时间占总生产时间的比例 | 安灯停线时间 / 总可用时间 × 100% | < 5% |

## 制造业具体应用案例

### 案例：安灯系统实施与效果

**背景**：某制造工厂机加工车间有8台机加工设备，月产量600万件。实施安灯前，质量问题主要靠巡检发现，平均问题发现延迟20分钟，导致批量报废时有发生。

**实施过程**：

1. 在每台机加工设备上方安装三色安灯塔灯
2. 在每台设备旁安装安灯拉绳和蜂鸣器
3. 在车间入口设置安灯状态电子看板
4. 培训所有操作员安灯使用方法和响应流程
5. 建立班组长-车间主任-工程师三级响应机制
6. 开发安灯数据记录和分析系统

**关键指标变化**：

| 指标 | 实施前 | 实施后（6个月） | 变化 |
|------|--------|----------------|------|
| 问题发现延迟 | 20分钟 | 1分钟 | -95% |
| 平均处理时间 | 35分钟 | 12分钟 | -66% |
| 批量报废次数 | 月均4次 | 月均0.5次 | -87% |
| 月报废金额 | ¥45,000 | ¥8,000 | -82% |
| 设备故障停机 | 月均18小时 | 月均7小时 | -61% |
| 操作员质量意识评分 | 65分 | 88分 | +35% |

## 常见误区

### 误区一：安灯拉动率越低越好

安灯拉动率低可能意味着操作员不敢拉动或不知道何时应拉动。在实施初期，安灯频率上升是正常现象，说明问题正在被暴露。真正的目标是降低重复问题率，而非降低安灯频率。

### 误区二：安灯只是一套硬件设备

安灯的核心是背后的响应机制和改善文化，而非灯和按钮。没有明确的升级协议、没有训练有素的响应团队、没有根本原因分析机制，安灯硬件只是摆设。

### 误区三：惩罚安灯拉动的人员

如果管理者因安灯拉动而批评或处罚操作员，操作员会倾向于隐藏问题，导致安灯系统失效。必须建立"鼓励暴露问题"的文化氛围。

### 误区四：安灯记录填写是额外负担

安灯记录是持续改善的数据基础。应简化记录表格，尽可能采用电子化方式记录，减少操作员的书写负担。同时定期展示安灯数据分析成果，让团队看到记录的价值。

### 误区五：安灯响应后不进行根本原因分析

如果每次安灯只是临时处理后就恢复生产，而不进行根本原因分析，同类问题会反复出现。建议对所有Level 2及以上的安灯事件进行根本原因分析。

### 误区六：安灯系统一成不变

安灯的触发条件、升级协议、响应时间目标应根据实际运行情况持续优化。不同阶段的关注重点不同，安灯系统应随之演进。
