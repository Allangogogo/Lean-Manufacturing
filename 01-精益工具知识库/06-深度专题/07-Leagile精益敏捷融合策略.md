# Leagile 精益敏捷融合策略

> 精益追求效率极致，敏捷追求响应极致——看似矛盾，实则互补。Leagile = Lean + Agile，通过解耦点设计，让上游精益驱动效率、下游敏捷驱动响应，是制造业面对"标准件大批量+定制件小批量"并存格局的核心策略。

---

## 为什么需要 Leagile？

### 制造业的双面挑战

```
传统产品市场                    新兴产品市场
────────────────                  ────────────────
标准件(某型号-某型号)                   定制件(特殊规格/材料)
大批量(万件/批)                   小批量(百件/批)
长生命周期(年)                    短生命周期(月)
价格竞争为主                      技术含量+响应速度竞争
客户需求稳定可预测                 客户需求多变难预测
→ 适合精益(效率驱动)              → 适合敏捷(响应驱动)

问题：两种逻辑在同一个工厂如何共存？
答案：Leagile — 用解耦点分离两种逻辑
```

### 纯精益的困境

| 场景 | 纯精益策略 | 困境 |
|------|-----------|------|
| 客户需求突变 | 拉动系统重新计算节拍 | 计划调整周期长，响应慢 |
| 小批量定制订单 | SMED减少换模时间 | 换模仍然频繁，效率下降 |
| 新产品导入 | 标准化后才能稳定生产 | 标准化周期长，错失市场窗口 |
| 供应链中断 | JIT零库存应对 | 没有缓冲=立即停产 |

### 纯敏捷的困境

| 场景 | 纯敏捷策略 | 困境 |
|------|-----------|------|
| 大批量标准件 | 快速响应+柔性生产 | 过度柔性=效率损失 |
| 稳定需求产品 | Sprint迭代 | 不必要的迭代=浪费 |
| 成本敏感市场 | 灵活配置资源 | 灵活性成本高，价格无竞争力 |

## Leagile 核心理论

### 解耦点 (Decoupling Point)

```
解耦点是精益与敏捷的分界线：

    供应商 → [精益区] → 解耦点 → [敏捷区] → 客户
              上游               下游
           效率驱动           响应驱动
           推式计划           拉式驱动
           预测驱动           订单驱动
           降成本             增价值
           大批量             小批量

解耦点的位置决定了精益和敏捷的边界：
├── 解耦点靠后（靠近客户）→ 更多精益，更少敏捷
├── 解耦点靠前（靠近供应商）→ 更多敏捷，更少精益
└── 最优解耦点 → 平衡效率与响应的总成本最低点
```

### 四种解耦策略

```
┌────────────────────────────────────────────────────────┐
│                  四种 Leagile 解耦策略                    │
├────────────────────────────────────────────────────────┤
│                                                        │
│  策略1: 面向库存解耦 (Make-to-Stock + Configure)       │
│  └── 解耦点：成品仓库                                   │
│  └── 适用：标准件（某型号-M24碳钢工件/工件）                 │
│  └── 上游：精益大批量生产→入库                           │
│  └── 下游：按库存配置+快速发货                           │
│                                                        │
│  策略2: 面向订单组装解耦 (Assemble-to-Order)            │
│  └── 解耦点：半成品仓库（热处理后/表面处理前）            │
│  └── 适用：同规格不同表面处理的产品                     │
│  └── 上游：精益生产半成品→入库                           │
│  └── 下游：按订单表面处理+包装                           │
│                                                        │
│  策略3: 面向订单制造解耦 (Make-to-Order)                │
│  └── 解耦点：原材料仓库                                  │
│  └── 适用：特殊材料/特殊规格产品                        │
│  └── 上游：精益采购+备料                                 │
│  └── 下游：按订单机加工+全流程定制                          │
│                                                        │
│  策略4: 面向订单设计解耦 (Engineer-to-Order)            │
│  └── 解耦点：设计/工程                                   │
│  └── 适用：航空航天/汽车OEM定制产品                     │
│  └── 上游：精益设计平台+标准化模块                        │
│  └── 下游：按客户要求设计+制造+验证                       │
│                                                        │
└────────────────────────────────────────────────────────┘
```

### 制造业解耦点选择矩阵

| 产品类型 | 需求特征 | 解耦策略 | 解耦点位置 | 精益区 | 敏捷区 |
|---------|---------|---------|----------|--------|--------|
| 标准碳钢工件 | 稳定大批量 | MTS+C | 成品仓 | 机加工→精加工→热处理→表面处理 | 配置+发货 |
| 标准不锈钢工件 | 中等批量 | ATO | 半成品(热处理后) | 机加工→精加工→热处理 | 表面处理→包装→发货 |
| 汽车级高强度工件 | 稳定中批量 | ATO | 半成品(精加工后) | 机加工→精加工 | 热处理→表面处理→包装 |
| 特殊规格产品 | 小批量多变 | MTO | 原材料 | 采购+备料 | 机加工→全流程 |
| 航空航天产品 | 极小批量+认证 | ETO | 设计 | 标准化模块+平台 | 设计→全流程→认证 |

## Leagile 实施框架

### 三层架构

```
┌─────────────────────────────────────────────────────┐
│                  Leagile 三层架构                     │
├─────────────────────────────────────────────────────┤
│                                                     │
│  第1层：精益基础设施层                                │
│  ├── 5S + 标准化作业（一切的基础）                     │
│  ├── TPM（设备可用性保障）                            │
│  ├── VSM（流程透明化）                               │
│  └── 质量体系（零缺陷基础）                           │
│                                                     │
│  第2层：解耦点管理层                                  │
│  ├── 解耦点定位（按产品线差异化）                      │
│  ├── 缓冲库存管理（解耦点库存策略）                    │
│  ├── 信息穿透（解耦点上下游信息同步）                   │
│  └── 计划协同（推式+拉式混合排产）                     │
│                                                     │
│  第3层：敏捷响应层                                    │
│  ├── 快速换模SMED（适应多品种）                       │
│  ├── 模块化设计（延迟差异化）                          │
│  ├── Sprint改善（2周迭代改善周期）                     │
│  └── 客户协同开发（早期介入设计）                      │
│                                                     │
└─────────────────────────────────────────────────────┘
```

### 混合排产策略

```
精益区排产（推式）：
├── 基于预测的长期计划（月/周）
├── 大批量、少品种、稳定节拍
├── 追求OEE最大化
├── 计划冻结期：3天
└── 产出目标：填充解耦点库存

敏捷区排产（拉式）：
├── 基于订单的短期计划（日/时）
├── 小批量、多品种、弹性节拍
├── 追求交付速度最大化
├── 计划冻结期：0（当天可调）
└── 产出目标：满足客户订单

解耦点协调：
├── 半成品库存水平监控
├── 上游计划调整信号
├── 下游订单优先级管理
└── 异常升级机制
```

## Leagile 的数字化赋能

### 信息穿透：解耦点上下游的数据流

```
传统问题：解耦点=信息断点
├── 上游不知道下游需求变化
├── 下游不知道上游产能状态
├── 库存水平不透明
└── 计划调整传递延迟

数字化解决方案：
├── 实时库存看板（解耦点半成品库存可视化）
├── 需求信号穿透（下游订单→上游计划自动调整）
├── 产能共享平台（精益/敏捷区产能动态分配）
├── AI排产优化（考虑解耦点约束的混合排产）
└── 数字孪生仿真（不同解耦点策略的What-if分析）
```

### AI驱动的动态解耦

```
静态解耦点 → 动态解耦点：

传统：解耦点固定，不随市场变化
I5.0：AI根据需求模式动态调整解耦点位置

决策因素：
├── 需求波动性（高波动→解耦点前移→更多敏捷）
├── 订单结构（定制比例高→解耦点前移）
├── 产能弹性（弹性大→解耦点后移→更多精益）
├── 供应链稳定性（不稳定→解耦点前移→缓冲更大）
└── 季节性因素（旺季→解耦点后移→更多备货）

AI动态解耦决策流：
├── 输入：需求预测+产能状态+供应链风险评估
├── 模型：约束优化（总成本最低+服务水平约束）
├── 输出：最优解耦点位置+库存策略+排产计划
└── 频率：每周重新评估，重大变化即时调整
```

## Leagile 绩效度量

### 传统精益KPI + 敏捷KPI 融合

| 维度 | 精益KPI | 敏捷KPI | Leagile综合KPI |
|------|---------|---------|---------------|
| 效率 | OEE | 产能利用率 | 加权OEE（精益区权重高） |
| 响应 | 生产周期 | 订单交付周期 | 分段周期（解耦点前后分别度量） |
| 库存 | 库存周转率 | 缺货率 | 解耦点库存健康度（不多不少） |
| 质量 | 不良率 | 客户投诉率 | 综合质量指数 |
| 成本 | 单件成本 | 总拥有成本 | 价值成本比 |
| 灵活性 | 换模时间 | 品种切换速度 | 品种-批量效率曲线 |

## 实施路径

### Leagile 成熟度5级

| 等级 | 名称 | 特征 | 典型表现 |
|------|------|------|---------|
| L1 | 纯推式 | 全厂统一推式生产 | 无解耦意识，计划驱动一切 |
| L2 | 隐性解耦 | 自然形成半成品缓冲 | 有库存但无策略管理 |
| L3 | 显性解耦 | 有意识设计解耦点 | 按产品线差异化策略 |
| L4 | 数字解耦 | AI动态调整解耦点 | 数据驱动+实时优化 |
| L5 | 自适应Leagile | 全链路自适应 | 需求变化→自动调整解耦+排产 |

### 实施步骤

```
Step 1 (1-2月): 诊断
├── 产品分类（ABC-XYZ分析）
├── 现有流程瓶颈识别
├── 需求模式分析（稳定/波动/季节性）
└── 确定各产品线解耦策略

Step 2 (2-4月): 设计
├── 解耦点位置设计
├── 缓冲库存策略设计
├── 混合排产规则设计
└── 信息流设计

Step 3 (4-8月): 试点
├── 选择1条产品线试点
├── 实施解耦点管理
├── 建立混合排产机制
└── 验证效果

Step 4 (8-14月): 扩展
├── 推广到所有产品线
├── 数字化工具上线
├── AI排产试点
└── 绩效体系完善

Step 5 (14-24月): 深化
├── AI动态解耦
├── 供应链协同Leagile
├── 客户端Leagile延伸
└── Leagile文化固化
```
