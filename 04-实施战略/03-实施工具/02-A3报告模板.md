# A3报告模板

> A3报告是精益思维的结构化表达工具，用一张A3纸（或等效页面）完整呈现问题分析和解决的全过程。

---

## A3报告结构（8个区块）

```
┌─────────────────┬─────────────────┐
│   1.背景/问题    │   2.当前状态     │
│   陈述          │                 │
├─────────────────┼─────────────────┤
│   3.目标状态     │   4.根因分析     │
│                 │                 │
├─────────────────┼─────────────────┤
│   5.对策方案     │   6.实施计划     │
│                 │                 │
├─────────────────┼─────────────────┤
│   7.效果确认     │   8.标准化/后续  │
│                 │                 │
└─────────────────┴─────────────────┘
```

---

## 区块1：背景/问题陈述

**填写指南**：说明为什么这个问题重要，与什么业务目标或痛点相关。

| 要素 | 内容 |
|------|------|
| 问题标题 | 简明扼要描述问题（如"机加工工序换模时间过长"） |
| 问题背景 | 这个问题为什么重要？与什么业务目标相关？ |
| 问题范围 | 问题影响哪些产品/工序/客户？ |
| 时间范围 | 问题存在多久？何时开始恶化？ |
| 量化影响 | 问题造成了多少损失（成本、质量、交付）？ |

**填写要点**：
- 用数据说话，避免主观描述
- 与业务战略或痛点建立关联
- 简明扼要，一段话讲清问题

---

## 区块2：当前状态

**填写指南**：描述问题发生时的实际情况，用数据和可视化呈现。

| 要素 | 内容 |
|------|------|
| 流程图 | 问题涉及的流程示意图 |
| 数据图表 | 问题相关的数据趋势图、柏拉图等 |
| 现场照片 | 问题现场的实际照片 |
| 浪费识别 | 识别到的浪费类型和位置 |
| 基线数据 | 当前的关键指标值 |

**填写要点**：
- 用图表替代大段文字
- 数据要准确，来源要标注
- 配合现场照片使问题可视化

---

## 区块3：目标状态

**填写指南**：描述改善后期望达到的理想状态。

| 要素 | 内容 |
|------|------|
| 目标描述 | 改善后应该是什么样子？ |
| 目标指标 | 量化的改善目标值 |
| 目标时间 | 希望何时达到目标状态 |
| 标杆参考 | 有没有内部或外部的标杆可以参考 |
| 客户价值 | 目标状态如何更好地服务客户 |

**填写要点**：
- 目标要SMART（具体、可衡量、可实现、相关、有时限）
- 目标要有挑战性但可实现
- 与当前状态形成清晰对比

---

## 区块4：根因分析

**填写指南**：分析问题的根本原因，而非表面症状。

| 方法 | 用途 |
|------|------|
| 鱼骨图 | 系统梳理所有可能原因 |
| 5Why分析 | 追溯根本原因（至少问5个为什么） |
| 帕累托分析 | 识别关键少数原因 |
| 验证 | 用数据验证根因假设 |

**5Why分析示例**：

```
问题：机加工工序不良率偏高
Why 1：为什么不良率高？→ 机加工件尺寸超差多
Why 2：为什么尺寸超差？→ 模具磨损快
Why 3：为什么模具磨损快？→ 模具材质不佳
Why 4：为什么材质不佳？→ 供应商质量不稳定
Why 5：为什么质量不稳定？→ 无供应商质量管控标准
→ 根因：缺乏供应商模具材质质量标准
```

**填写要点**：
- 至少找到2-3个关键根因
- 用数据验证根因假设，不要凭直觉
- 区分直接原因和根本原因

## 区块5：对策方案

**填写指南**：针对根因制定对策方案。

| 要素 | 内容 |
|------|------|
| 对策清单 | 针对每个根因的对策 |
| 对策评估 | 每个对策的效果、成本、可行性评估 |
| 选定对策 | 最终选定实施的对策 |
| 预期效果 | 每个选定对策的预期改善效果 |

**对策评估矩阵**：

| 对策 | 效果（1-5） | 成本（1-5） | 可行性（1-5） | 总分 | 选择 |
|------|-----------|-----------|-------------|------|------|
| 对策A | | | | | |
| 对策B | | | | | |
| 对策C | | | | | |

**填写要点**：
- 对策要针对根因，而非症状
- 考虑对策的副作用和风险
- 优先选择低成本、高效果的对策

## 区块7：效果确认

**填写指南**：实施后对照目标验证效果。

| 指标 | 改善前 | 目标值 | 改善后 | 达成率 |
|------|--------|--------|--------|--------|
| 指标1 | | | | |
| 指标2 | | | | |
| 指标3 | | | | |

**效果确认方法**：
- [ ] 数据对比（改善前后至少对比4周数据）
- [ ] 现场验证（实际观察改善效果）
- [ ] 利益相关方确认（操作工、班组长、质量等确认）
- [ ] 财务效益核算

---

## 区块8：标准化/后续

**填写指南**：将改善成果标准化，并规划后续行动。

| 要素 | 内容 |
|------|------|
| 标准化措施 | 需要更新哪些标准、流程、文件 |
| 水平展开 | 这个改善能否推广到其他区域/产品 |
| 遗留问题 | 还有哪些问题需要后续解决 |
| 经验教训 | 从这次改善中学到了什么 |
| 下一步行动 | 后续的改善方向 |

**标准化检查清单**：
- [ ] 标准作业已更新
- [ ] 培训已完成
- [ ] 目视化管理已更新
- [ ] 管理板已更新
- [ ] 上游/下游已通知
- [ ] 审核计划已制定

## 使用说明

1. **适用场景**：问题解决、项目管理、状况报告、提案申请
2. **编制时间**：简单问题1-2天，复杂问题1-2周
3. **审核流程**：编制人→直接主管→精益推进办公室
4. **版本管理**：每次更新标注版本号和日期
5. **存档要求**：所有A3报告统一存档，作为组织知识积累

**A3思维的核心**：
- 用一张纸讲清楚问题的来龙去脉
- 以事实和数据为基础，避免主观判断
- PDCA循环的结构化表达
- 促进对话和共识，而非单向汇报
